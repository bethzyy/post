Claude Code 记忆文件说明 - 今日头条版

Claude Code 使用两种文件来存储和记忆项目相关信息：CLAUDE.md 和 MEMORY.md。它们有不同的用途和特点。

图：Claude Code 的双记忆系统

对比表格

对比维度 CLAUDE.md MEMORY.md
文件位置 项目根目录
C:\项目\CLAUDE.md		 用户记忆目录
~/.claude/projects/.../memory/
主要作用 项目文档，描述项目架构、技术栈、使用方法 个人经验记录，记录解决问题的经验和学习笔记
内容类型 静态信息：项目概述、命令列表、架构图、已知问题 动态学习: Bug 修复经验、用户偏好、调试技巧
是否提交 Git 是，作为项目文档提交到仓库 否，个人本地文件，不提交到仓库
共享范围 团队共享，所有使用该项目的开发者可见 个人专属，只有当前用户的 Claude Code 会读取
更新频率 项目结构变化时更新 遇到问题时随时记录
类似物 项目的"使用说明书" Claude 的"学习笔记"

图：CLAUDE.md 作为项目的"使用说明书"

CLAUDE.md 详解

CLAUDE.md 是项目级别的文档文件，放置在项目根目录下。它的主要目的是向 Claude Code 说明这个特定项目的基本信息。

典型内容结构

# CLAUDE.md

## Project Overview
- 项目名称和简介

## Commands
- 开发、构建、测试命令

## Architecture
- 技术栈
- 数据流图
- 核心组件说明

## Known Issues / Solved Issues
- 已知问题
- 已解决的问题

适用场景

  • 项目首次设置时创建
  • 向 Claude 介绍项目结构
  • 记录项目特定的命令和配置
  • 记录团队共知的架构决策

MEMORY.md 详解

MEMORY.md 是用户级别的自动记忆文件，存储在 Claude Code 的记忆目录中。它记录 Claude 在与用户交互过程中学到的经验。

典型内容结构

# Memory

## Project: 项目名称
**路径:** C:\path\to\project

## Bug Fix: 问题标题
**日期:** 2026-03-02

### 问题描述
描述遇到的问题

### 根本原因
分析问题产生的原因

### 解决方案
详细的修复步骤和代码

### 关键要点
提炼的经验教训

适用场景

  • 记录 Bug 修复的具体经验
  • 记录用户的工作偏好
  • 记录调试过程中的发现
  • 跨会话保持上下文记忆

最佳实践建议

  1. CLAUDE.md 应该包含：项目概述、技术栈、常用命令、架构说明、API 文档等静态信息
  2. MEMORY.md 应该包含：具体的 Bug 修复经验、用户偏好、调试技巧等动态学习内容
  3. 重要修复经验：建议同时记录在两个文件中 - MEMORY.md 作为个人笔记，CLAUDE.md 的 Solved Issues 部分作为项目文档
  4. 保持简洁：MEMORY.md 文件过大时，按主题拆分为多个文件（如 debugging.md、patterns.md）

文件 记录内容

- 解决方案：使用 { capture: true } 在捕获阶段拦截事件
- 关键要点：事件冒泡 vs 捕获、XTerm 事件优先级
